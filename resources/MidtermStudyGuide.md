# Exam Study Guide
The exam will be an overview of all the materials covered in class for the semester so far. The exam will be a one hour timed Canvas Quiz that is open-book. You are free to use your notes, lectures slides, and other course materials and resources to complete the exam. You may **NOT** work with another person or use generative AI tools for this exam. Below is a high-level study guide to help organize your preparation efforts. If you are using the course agent-template, use the `quiz` or `concept-explain` skills to help with your study efforts (please use `git pull` to access the latest version first!). The exam content will include but is not limited to the following:

### General
* Identify concepts belonging to the Requirements and Design SDLC phases
* Define general terms related to software engineering

### Software Processes
* Name plan-driven and iterative process models (Waterfall, V-Model, Spiral, Incremental, Prototyping, XP/Scrum/Kanban)
* Explain the advantages and disadvantages of iterative and plan-driven processes
* Describe the SDLC phases and the goal of each
* Select an appropriate process for a given scenario, and justify your process choice

### Project Management and Team Practices
* Compare and contrast different agile-based processes and concepts
* Define different agile meetings (_e.g.,_ sprint planning, sprint review, retrospective, stand-up, triage)
* Apply estimation techniques and agile practices to a given scenario, and justify your choice
* Define common `git` commands and version control practices
* Understand the difference between `git` objects (_e.g.,_ commit, blob, tree, etc.)
* Explain common practices on version control platforms such as GitHub (_e.g.,_ branches, issues, etc.)

### Requirements
* Explain the difference between requirements analysis, specifiction, elicitation, and engineering
* Differentiate functional from non-functional requirements
* Describe requirements elicitation techniques
* Write a user story for a given scenario
* Understand the difference between requirements modeling UML diagrams
* Describe techniques for requirements prioritization

### Design
* Understand the difference between high-level, low-level, database, and user interface design
* Name high-level design architectures and low-level design pattern families
* Understand different software design concepts (i.e. abstraction, modularity, etc.)
* Decompose a given program to expose usability, low-level design, and high-level architecural problems
* Explain the advantages and disadvantages of using design patterns
* Translate between design diagrams and code
* Explain the difference between design modeling UML diagrams
* Apply Nielsen's design herustics for a given scenario
* Select a UI design process to improve a user interface
